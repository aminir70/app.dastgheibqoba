# ربات پاسخگوی فارسی بر پایه‌ی فایل‌های شما (RAG)

یک سامانه‌ی کامل که فقط و فقط از روی فایل‌های شما (PDF، Word، عکس) به سؤالات پاسخ می‌دهد،
از OpenAI استفاده می‌کند، پنل مدیریت دارد و محدودیت پیام/توکن برای کاربران را اعمال می‌کند.

تمام متن‌ها و رابط کاربری فارسی و راست‌به‌چپ هستند.

---

## این سامانه چطور کار می‌کند (RAG)

به‌جای اینکه مدل از دانش عمومی‌اش جواب بدهد، این مسیر طی می‌شود:

1. شما در پنل، فایل را آپلود می‌کنید.
2. متن استخراج می‌شود:
   - **PDF متنی** → استخراج مستقیم (سریع، بدون هزینه).
   - **PDF اسکن‌شده یا عکس** → OCR فارسی با Tesseract (`fas`). صفحاتی که متن قابل‌استخراج ندارند خودکار تشخیص داده و OCR می‌شوند.
   - **Word (.docx)** → استخراج پاراگراف‌ها و جدول‌ها.
3. متن به قطعات کوچک (chunk) تقسیم و برای هر قطعه یک «امبدینگ» با `text-embedding-3-large` ساخته می‌شود.
4. قطعات و بردارها در PostgreSQL + `pgvector` ذخیره می‌شوند.
5. هنگام سؤال: سؤال هم امبدینگ می‌شود، نزدیک‌ترین قطعات پیدا می‌شوند، و **فقط همان قطعات** به مدل پاسخ‌دهی داده می‌شوند با این دستور که «اگر پاسخ در منابع نبود بگو پیدا نشد».
   - اگر هیچ قطعه‌ای از حد آستانه‌ی شباهت رد نشود، اصلاً مدل صدا زده نمی‌شود و پاسخ «در منابع پیدا نشد» برمی‌گردد (هم جلوی توهم را می‌گیرد، هم هزینه را).

---

## معماری

```
[ویجت چت]  [پنل مدیریت]
      \         /
     FastAPI (api)  ──► PostgreSQL + pgvector   (کاربر، تنظیمات، مصرف، بردارها)
        │   ▲
        │   └── OpenAI API (امبدینگ + پاسخ)
        ▼
     Redis  ──►  Worker  (پردازش فایل‌های سنگین در پس‌زمینه)
```

پردازش فایل سنگین (مثلاً PDF ۵۰۰ صفحه‌ای) در **worker** و در صف انجام می‌شود تا موقع آپلود، سرور قفل نشود.

## راه‌اندازی سریع

پیش‌نیاز: فقط **Docker** و **Docker Compose**.

```bash
cp .env.example .env
# .env را باز کنید و این موارد را حتماً تنظیم کنید:
#   OPENAI_API_KEY   = کلید OpenAI شما
#   ADMIN_PASSWORD   = رمز پنل مدیریت
#   JWT_SECRET       = یک رشته‌ی تصادفی بلند

docker compose up --build
```

سپس:

- پنل مدیریت: <http://localhost:8000/admin>
- صفحه‌ی نمونه‌ی ویجت چت: <http://localhost:8000/demo>
- مستندات API: <http://localhost:8000/docs>

ترتیب کار: وارد پنل شوید → چند فایل آپلود کنید → صبر کنید وضعیت‌شان «آماده» شود → در صفحه‌ی demo سؤال بپرسید.

## افزودن ویجت به سایت خودتان

این یک خط را قبل از `</body>` در هر سایتی بگذارید:

```html
<script src="https://دامنه-شما/static/widget.js" data-title="دستیار پاسخگو"></script>
```

با `data-api` می‌توانید آدرس سرور را صریح بدهید اگر ویجت روی دامنه‌ی دیگری است.

## محدودیت پیام برای کاربران

از پنل → «تنظیمات» قابل تنظیم است و هر دو روش با هم کار می‌کنند:

- **سقف پیام روزانه‌ی هر کاربر** (پیش‌فرض ۲۰)
- **سقف توکن ماهانه‌ی هر کاربر** (پیش‌فرض ۱۰۰٬۰۰۰)
- **سقف بودجه‌ی روزانه‌ی کل** (پیش‌فرض ۱۰ دلار) — محافظ کیف پول؛ با عبور از این مقدار، کل سرویس تا فردا قطع می‌شود.

شناسایی کاربر با **نام کاربری و رمز عبور** انجام می‌شود. کاربر در ویجت خودش ثبت‌نام می‌کند
(نام کاربری + رمز) و سپس وارد می‌شود. رمزها با PBKDF2 (کتابخانه‌ی استاندارد پایتون، بدون
وابستگی اضافه) هش و ذخیره می‌شوند.

> اگر می‌خواهید بدون ورود و کاملاً عمومی باشد، در تنظیمات «اجبار ورود کاربر» را خاموش کنید.
> توجه: در این حالت محدودیت «هر کاربر» معنا ندارد و فقط سقف بودجه‌ی کل از شما محافظت می‌کند.
>
> روش پیامکی فعلاً غیرفعال است؛ تنظیمات Kavenegar در `.env` برای فعال‌سازی مجدد در آینده باقی مانده.

## نکته درباره‌ی دسترسی به OpenAI

شما گفتید سرور خارج از ایران و دسترسی مستقیم است، پس نیازی به تنظیم اضافه نیست.
اگر روزی روی سروری بودید که به OpenAI دسترسی مستقیم ندارد، فقط کافی است
`OPENAI_BASE_URL` را در `.env` به آدرس پراکسی سازگار با OpenAI تنظیم کنید؛ بقیه‌ی کد تغییری نمی‌کند.

## هزینه‌ها

- **یک‌بار هنگام آپلود:** امبدینگ کل متن فایل‌ها. برای یک PDF ۵۰۰ صفحه‌ای متنی، چند صد هزار توکن امبدینگ ≈ چند سنت.
- **هر سؤال:** یک امبدینگ کوچک برای سؤال + توکن‌های پاسخ مدل. با `gpt-5.4-mini` معمولاً کسری از یک سنت.

نرخ‌ها در پنل (`model_prices`) قابل ویرایش‌اند و برای تخمین بودجه استفاده می‌شوند؛
حتماً با صفحه‌ی قیمت روز OpenAI تطبیق‌شان بدهید.

## آنچه آماده است

- استخراج متن از PDF/Word/عکس + OCR فارسی خودکار برای اسکن‌ها
- قطعه‌بندی، امبدینگ و جست‌وجوی برداری
- پاسخ‌دهی سخت‌گیرانه «فقط از منابع» + ذکر منبع
- **پاسخ استریم‌شونده (تایپ‌شونده) به‌صورت زنده**
- **تاریخچه‌ی گفتگو:** ذخیره و نمایش پیام‌های قبلی هر کاربر + دکمه‌ی «گفتگوی جدید»
- **گفتگوی چندمرحله‌ای (RAG آگاه از تاریخچه):** سؤالات دنباله‌دار با ضمیر/ارجاع («قیمتش چنده؟») درست بازیابی و پاسخ داده می‌شوند
- پنل مدیریت: داشبورد مصرف، آپلود/حذف فایل، تنظیمات، مدیریت و مسدودسازی کاربران
- ورود کاربر با نام کاربری و رمز عبور + محدودیت پیام/توکن + سقف بودجه
- ویجت چت قابل‌جاسازی در هر سایت
- اجرای کامل با یک دستور Docker

## پیشنهاد برای محیط تولید (Production)

- پشت یک reverse-proxy با HTTPS (مثلاً Caddy یا Nginx) قرار دهید و CORS را به دامنه‌های مجاز محدود کنید.
- محدودیت نرخ (rate-limit) سطح زیرساخت روی `/api/auth/request-otp` بگذارید تا از سوءاستفاده‌ی پیامکی جلوگیری شود.
- برای ترافیک بالا، تعداد worker و instanceهای api را افزایش دهید و فایل‌های آپلودی را روی استوریج پایدار (S3 و مشابه) ببرید.
- نسخه‌گیری منظم از پایگاه داده.
- اگر مدل امبدینگ یا بُعد آن را عوض کردید، فایل‌ها باید دوباره پردازش شوند (بُعد ستون بردار ثابت و برابر ۱۵۳۶ است).
