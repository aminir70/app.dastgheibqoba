# بکاپ

دو لایه: محلی (روی همان سرور) و بیرونی (رمزنگاری‌شده روی فضای ابری).
بکاپ محلی برای بازیابی سریع است؛ بکاپ بیرونی برای وقتی که خودِ سرور از
بین برود.

## بکاپ محلی — `scripts/backup.sh`

| چه چیزی | چطور | چند نسخه |
|---|---|---|
| `library.sqlite` | `sqlite3 .backup` سپس gzip | ۱۴ روز |
| `.env` و `chatbot/.env` | tar با دسترسی ۰۶۰۰ | ۱۴ روز |
| `books/`, `public/gallery|covers|content|audio|ticket-files|icons` | `rsync --link-dest` | ۷ روز |

با WAL فعال، `cp library.sqlite` بکاپ ناقص می‌دهد چون نوشته‌های داخل فایل
`-wal` را از قلم می‌اندازد. `.backup` تنها روش درست است.

اسنپ‌شات فایل‌ها هارد-لینک است: چون نام فایل‌های آپلودی تصادفی و محتوایشان
تغییرناپذیر است، نسخهٔ دوم به بعد تقریباً فضایی نمی‌گیرد.

```bash
bash scripts/backup.sh                 # اجرای دستی
bash scripts/backup.sh --install-cron  # هر شب ۳:۱۷
```

اگر فضای آزاد کمتر از ۲ گیگ باشد، بکاپ فایل‌ها رد می‌شود تا دیسک پر نشود.

## بکاپ بیرونی — `scripts/backup-remote.sh`

`backup.sh` در پایان کار خودش این را صدا می‌زند. اگر rclone پیکربندی نشده
باشد بی‌صدا رد می‌شود، پس تا وقتی تنظیمش نکرده‌اید چیزی خراب نمی‌شود.

**همه‌چیز قبل از خروج از سرور رمزنگاری می‌شود** — هم محتوا و هم نام
فایل‌ها. اسکریپت اگر مقصد از نوع `crypt` نباشد اجرا نمی‌شود. دلیلش این
است که بکاپ شامل `JWT_SECRET`، رمز ادمین، کلید OpenAI، هش رمز کاربران و
تیکت‌های شخصی مردم است.

### پیکربندی — یک بار

**۱) نصب rclone روی سرور**
```bash
sudo apt install -y rclone
```

**۲) گرفتن توکن روی کامپیوتر خودتان** (اینجا مرورگر لازم است، روی سرور نه)

rclone را روی ویندوز/مک خودتان نصب کنید و بزنید:
```bash
rclone authorize "drive" "{\"scope\":\"drive.file\"}"
```
مرورگر باز می‌شود، اجازه می‌دهید، و یک JSON بلند چاپ می‌شود. کپی‌اش کنید.

> `scope drive.file` یعنی rclone فقط به فایل‌هایی که خودش می‌سازد دسترسی
> دارد، نه به بقیهٔ محتوای درایو شما.

**۳) ساخت remoteها روی سرور**
```bash
rclone config create gdrive drive scope drive.file token '<JSON مرحله ۲>'

rclone config create gcrypt crypt remote gdrive:app-backups \
  password  "$(rclone obscure 'یک-رمز-قوی-بسازید')" \
  password2 "$(rclone obscure 'یک-نمک-متفاوت-بسازید')"

chmod 600 ~/.config/rclone/rclone.conf
```

**۴) رمز و نمک را بیرون از سرور نگه دارید**

این تنها بخشی است که خودکار نمی‌شود و مهم‌ترین بخش است: اگر سرور از بین
برود و رمز را نداشته باشید، بکاپ‌ها **غیرقابل بازیابی‌اند**. آن دو رشته را
در یک password manager یا جای امن دیگری ذخیره کنید. یک نسخه از
`~/.config/rclone/rclone.conf` هم جای امنی نگه دارید.

**۵) تست**
```bash
bash scripts/backup.sh          # اجرای کامل: محلی + آپلود
rclone ls gcrypt: | head
tail -20 ~/backup-remote.log
```

آپلود اول ~۵۰۰ مگابایت است و ممکن است نیم ساعت طول بکشد. شب‌های بعد فقط
فایل‌های تازه می‌روند (چند مگابایت).

## بازیابی

```bash
# همه‌چیز
rclone copy gcrypt: /مسیر/بازیابی -P

# فقط دیتابیس یک روز خاص
rclone copy gcrypt:db/app-2026-08-27.sqlite.gz . && gunzip app-2026-08-27.sqlite.gz

# فقط فایل‌های آپلودی
rclone copy gcrypt:files /مسیر/بازیابی -P
```

روی مقصد این ساختار هست:

```
gcrypt:db/     نسخه‌های تاریخ‌دار دیتابیس (۱۴ روز)
gcrypt:env/    نسخه‌های تاریخ‌دار .env (۱۴ روز)
gcrypt:files/  آینهٔ وضعیت جاری فایل‌های آپلودی
```

اسنپ‌شات‌های تاریخ‌دارِ فایل‌ها فقط محلی نگه داشته می‌شوند (۷ روز)؛ بیرون
یک نسخهٔ جاری کافی است و پهنای باند را چند برابر نمی‌کند.
